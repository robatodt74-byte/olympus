# 出典とObsidianを使った知識の蓄積

2026-10-15のユーザー指定: 公式資料・一般に受け入れられた実務知識を活用し、Obsidianへナレッジと失敗原因の仮説を残して再利用する。

## 出典から知識へ

- 公式文書・標準規格・大学の指針・根拠ある専門資料を優先する。公式の製品仕様、分野で広く使われる慣行、個人の提案は区別し、「よく見かける」を普遍的な正しさと扱わない。
- 調べて終わらず、再利用価値がある内容は要点、適用条件、例外、根拠リンク、対象版・確認日を残す。全文転載や同じ説明の大量複製を避ける。
- 再利用前に対象と版・時点が合うか確認する。古い記述は経緯として残し、現行の判断を識別できるようにする。

## Obsidianで保存するもの

- 繰り返し使う知識、判断理由、重要な仕様・検証結果、再発し得る失敗とその原因仮説を、既存Vaultの関連ノートへ積極的に蓄積する。
- 明示済みの保存先と既存構成を確認し、類似ノートを検索して更新・追記を優先する。索引や関連ノートへのリンクを残し、孤立したノートを増やさない。
- 保存先が未確定・複数候補なら内容を先に準備し、保存先だけ確認する。新しいVaultやBrainフォルダを自動作成しない。
- 通常の完了報告を毎回そのまま保存する必要はない。後から検索・再利用する価値で選ぶ。作業履歴と再利用する手順は分けてリンクする。
- 保存後は内容とリンクを読み戻す。保存できていないものを「学習済み」「蓄積済み」と報告しない。

## 失敗・原因仮説の記録

必要な項目だけ使い、未確認は空欄や「未確認」として残す。

| 項目 | 記録内容 |
|---|---|
| 症状・検索語 | 実際のエラー、期待との差、発生日時、環境・版 |
| 事実 | 実行した操作、再現条件、ログや差分への参照 |
| 原因仮説 | 候補、支持する根拠、反証、未確認点、検証方法 |
| 試行と結果 | 何を変え、何が変わったか。失敗した方法も残す |
| 対処 | 暫定回避と恒久対策を区別し、適用条件を記す |
| 状態 | 未検証／支持あり／確認済み／棄却。判断日と根拠を付ける |

再発時は症状・環境で検索して過去の仮説と試行を利用する。同じ症状だけで同じ原因と断定せず、現行環境で小さく検証する。仮説を事実へ格上げするには証拠が必要。秘密情報や不要な個人情報は記録しない。

## Lessons Learned

再発・修正からの経験蓄積と次回確認には、利用環境に別途導入されている `lessons-learned` Skill があれば、その手順を確認する。経験の共通入口は、利用者が指定した既存VaultのLessons Learnedノートとする。Skillや保存先を未確認のまま利用済みとせず、案件に既存の経験ノートがある場合はその正本を維持し、共通入口から参照する。Skill本体と個人ノートはこのリポジトリには同梱しない。

記録したこと、対策を実装したこと、次の該当作業で有効性を確認したことを区別する。新しい基準への昇格は適用条件と効果を確認し、単発の変更や未検証の仮説を全案件へ広げない。
