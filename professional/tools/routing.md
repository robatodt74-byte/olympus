# Skills・Plugins・CLIの参照

適用: 作業手段を選ぶとき、重複発動や指示競合があるとき。専門文書は品質と判断基準、Skillは実行手順、Connector/API/CLIは操作手段を担当する。

## 選択表

| 対象 | 主な手段 | 適用境界 |
|---|---|---|
| 過去のエージェント判断 | ctx-agent-history-search / ctx | 現行コードの代わりにしない。利用不能なら既存の記録を使う。環境構築は別範囲 |
| 現在のコード・ファイル | rg、Git、必要なファイルの読み取り | 単純検索からグラフ構築へ拡張しない |
| 既存グラフで関係を調べる | graphify | 読み取りと生成・更新を分ける。通常の質問でインストールしない |
| OpenAI製品・APIの仕様 | openai-docs / 公式資料 | Context7で同じ調査を繰り返さない |
| その他のライブラリ・SDK・CLI仕様 | context7-mcp / 公式資料 | 取得済み資料を再利用。技術名への言及だけでは発動しない |
| 実装の簡素化 | ponytail | 要件・検証・アクセシビリティを削らない。文章や秘書業務へ持ち越さない |
| テスト先行の開発 | tdd | 既存の仕様・テスト境界が明確なら再承認せず進める |
| 難しい不具合の診断 | diagnosing-bugs | 再現手段と検証を重視。単純な修正に全工程を強制しない |
| コード差分のレビュー | code-review | コミット済み・未コミット・未追跡を依頼どおり選ぶ。レビューだけで設定を導入しない |
| UI制作・改訂 | hallmark等の適合するSkill | 既存体系を優先。分かっている要件を再質問しない |
| Word/PDF/Slides/Sheets | 形式別の作成Skill、接続先の編集Skill | ローカル成果物とクラウドの対象を区別。指定テンプレートを優先 |
| 指定先のIssue・予定登録 | plan、対応Connector | 案だけなら登録しない。外部登録の依頼と対象が明確なら再承認不要 |
| 大きな独立調査 | research | 委任が有効な場合の候補。小さな仕様確認に必ず並列調査を追加しない |

環境開発の `issue-triage`、`issue-executor`、`debug-and-repair`、`focused-review`、`coderabbit-review`、`typesafe-ai` は当該リポジトリの指示に従う。ここに名前があるだけで他の案件の必須要件にしない。

Claudeとの分業を検討する場合は[Claude連携](../collaboration/claude.md)を参照する。接続と効果を確かめず、モデルの得意分野を断定しない。

## ブラウザ操作の優先順位（2026-10-18）

- 目的に適したCLI・API・専用コネクターを優先する。ブラウザが必要ならAsideの `aside repl` で直接操作し、computer-useはCLI等で扱えない画面や視覚確認が必要な場合に限定する。
- `aside exec` はAside内のAIへの委任であり、直接操作とは区別する。別AIへの分業はユーザーが指定した範囲で行う。MCP接続の追加は必要性を確認して行う。
- 認証を伴う操作前に、CLIの対象アカウント・ブラウザプロファイル・サービスのログイン先を照合する。画面で確認したGoogleアカウントとCLI・コネクターの接続先が同じとは推測しない。
- 通常の許可済み作業は自律的に進める。追加権限、未許可の対外送信・公開・課金、重要なアクセス変更、破壊的操作等で承認が必要な場合は、対象・操作・影響・必要な理由を実行直前に示して承認を得る。実行環境の権限制限は所定の承認機構を使い、迂回しない。
- パスワード・トークンはMD・Skill・Obsidian・Git・作業ログ・Sheetsへ転記しない。コマンド引数や出力への露出を避け、既存の安全な認証経路を優先する。

## Cavemanの適用範囲（2026-10-18）

- Cavemanは会話の表現を簡潔にする。実装範囲・検証・調査の深さを削る指示ではない。Ponytailは実装の簡素化を担当し、役割を混同しない。
- 日本語の自然な敬語を維持する。重要な根拠・不確実性・例外・否定・未確認事項・レビュー指摘は省略しない。「No hedging」は不要な言い回しの削減に限定し、確度を偽らない。
- 必須の進捗報告、エラー報告、承認確認、引用・成果物リンク、指定された出力形式を優先する。詳細説明を求められたら必要な詳しさへ戻す。20語等の英文目安を日本語の機械的な文字数制限にしない。
- 保存するコード・文書・PR・Issue・第三者宛の文章は成果物側の品質基準に従う。レポートの情報量、出典、デザインの可読性を削らない。
- 通常版Skillのみ導入。`/caveman`等の指定時に適用し、`stop caveman`／`normal mode`／「通常の説明に戻して」で解除する。導入自体を全チャット常時ONと扱わない。ultracave・megacave・caveman-compress・Hook・プロキシは未導入なので利用できると装わない。
- 更新時は発動条件・持続範囲・外部送信・Hook追加の変化を再確認する。上位指示とユーザーの明示要件が優先する。

## 接続を調べる場合

棚卸し・認証問題・操作先や権限の確認時だけ[connections.md](connections.md)を読む。導入済みやツール表示だけで接続成功としない。

## 指示の競合

適用範囲を先に絞り、ユーザーの明示要件と対象の規則を一般的なSkillのレシピより優先する。上位の実行制約は回避しない。同じチェックを複数Skillが要求しても、対象版と範囲が一致する検証結果は再利用する。既存の許可を取り直さず、参照先が要求するという理由だけで依頼外の変更や外部送信をしない。

Skillの更新で指示が戻る可能性があるため、更新後は該当する発動条件・質問条件・副作用を再確認する。全文を常時読み込む監視や自動修正は追加しない。

根拠: [OpenAI公式・Build skills](https://developers.openai.com/plugins/build/skills)（2026-10-15確認）。用途と発動条件を絞り、詳細を補助文書へ置く設計に従う。

## 読込・実行の効率

品質を第一、完了までの総トークン消費を第二とする。名前・説明で主手順を選び、必要な本文・参照だけ読む。同じ用途の手順や有効な検証を重ねない。検索出力、再利用、分業資料、計測を調整する場合は[トークン効率](token-efficiency.md)の該当節だけ参照する。
