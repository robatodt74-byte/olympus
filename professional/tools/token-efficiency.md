# 品質を守るトークン効率

適用: 資料・Skillの選択、検索とツール出力、再利用、分業の準備、消費の評価。品質・正確性と必要な検証を第一に、受入可能な成果までの総トークン消費を第二に最適化する。

## 作業時の選択

- 単純な質問や小修正には不要なSkillを追加しない。必須の参照指示は守り、名前・説明から適切な主手順を選ぶ。追加Skillは主手順が覆わない具体的な不足がある場合に読む。
- 既読の資料・一次資料・検証結果は対象版、範囲、適用条件が変わらなければ再利用する。文脈から失われた、更新された、鮮度が必要な場合は該当部分を再取得する。
- 同じ用途のSkillを重ねて実行しない。名前が同じだけで同一内容と判断せず、適用範囲と現行ルールに従って選ぶ。重複整理を理由にパッケージを自動削除・無効化しない。
- disable-model-invocation等の明示呼出し条件や分業権限を節約目的で変更しない。情報不足・不確実性・重要なレビュー指摘を省略しない。

## 検索・ツール出力

- 現行コードはrg等でファイル・語・範囲を絞ってから読む。広い検索は所在不明時に限り、結果が途切れたら検索条件を狭める。出力打切りを「該当なし」と扱わない。
- 長いログは安全な保存先に残し、会話へは結果、件数、失敗箇所、必要な前後、参照先を出す。秘密・個人情報を生ログへ無制限に保存しない。
- ツールが選択列・検索条件・件数制限を持つ場合は利用する。ただし必要な全件集計や完全性の確認ではページング・母数・欠落を確認する。
- 定型集計・形式検証・差分抽出は既存CLIやスクリプトを再利用する。反復の見込みがある場合のみ小さな処理にし、未知の業務判断まで機械化しない。

## 記録・引継ぎ

- ユーザー向け進捗は関連3〜5操作を目安に節目でまとめる。長い処理中は必要な更新を行い、エラー・権限不足・重要な判断待ちは即時に共有する。機械の証跡は間引かない。

- 知識の正本は[知識運用](../knowledge/operations.md)に従う。判断、根拠、確認日、適用条件、再確認の契機を残し、説明全文のコピーを増やさない。
- 許可された分業には目的、対象版、担当範囲、受入条件、必要資料だけ渡す。全履歴を既定で複製しない。時間短縮と総トークン削減を分け、重複調査・統合作業も含める。
- 要約・引継ぎでは明示制約、承認範囲、決定、現在の状態、未解決、次の行動、証拠への参照を保持する。短縮で権限や未確認事項を落とさない。

## キャッシュ・圧縮の扱い

- APIを設計する場合は安定した共通指示と変動入力を区別する。キャッシュの適用と料金は対象モデルの公式仕様と実測で確認する。
- 圧縮は入力を減らすがキャッシュ一致を変える場合がある。機械的な定期圧縮、履歴削除、モデル変更を節約策として自動導入しない。
- API料金、GUIの契約利用枠、トークン量、実時間を混同しない。この文書はキャッシュ設定を変更せず、GUIの利用枠削減を保証しない。

## 計測と業務への非干渉

- 既存の取得可能なusageを使い、入力・キャッシュ済み入力・出力・推論の包含関係を確認する。キャッシュや推論の内数を再加算しない。不明はnull/未測定とする。
- 受入結果、重大見落とし、修正往復、実時間と併せて比較する。文書の短さや静的検証成功だけで節約効果を主張しない。
- 稼働中業務と競合し得る比較実験、監視Hook、ログ常時収集、別AI起動、実サービスの書込・再実行はこの方針だけで開始しない。
- ユーザーが稼働検証を延期した場合は差分・参照・構文の静的確認までに留める。実測は安全な時点と対象が決まってから行う。
